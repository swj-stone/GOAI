# CampusMatch 答辩问题库

## 1. 这不就是简历匹配加聊天机器人吗？

不是。普通匹配工具给结果，CampusMatch 管理的是完整任务生命周期：同意、材料解析、证据抽取、岗位规范化、逐项匹配、辅导、事实审计、人工审批、导出和经验沉淀。核心资产是可复用 Skills、结构化协作协议、证据链和运行验证，而不是一个聊天界面。

## 2. 为什么一定需要多个 Agent？

材料事实、岗位规则、匹配决策、辅导建议和审计的目标与权限不同。将它们拆开可以限制上下文、独立评测、明确失败责任，并让 Audit 对 Coach 和 Match 保持独立。如果合并成一个 Agent，它既生成又自审，边界和证据会变弱。

## 3. Career Navigator 为什么不参与所有内部对话？

它负责用户沟通、目标、路由、状态和汇总。Worker 之间通过结构化任务信封与文件引用协作。这样避免中心 Agent 成为 Token、延迟和上下文污染瓶颈，也更符合 AgentTeams Manager–Workers 分工。

## 4. 匹配分怎么计算？

先逐条判断要求状态，再根据模式权重聚合五个维度。匹配度和置信度分开：匹配度表示现有证据与岗位的契合，置信度表示材料是否足够支持判断。风险性 JD 条件不进入评分，缺证也不等于能力为零。

## 5. 五维权重是否主观？

首版权重是可解释的基线，不宣称为最优。系统保存权重版本，并通过就业老师标注和固定评测集调整。学校可以在合法、公平的边界内配置，但敏感属性永远不允许加入特征。

## 6. 如何防止 AI 编造简历经历？

所有事实性句子必须关联 `evidence_ref`。Coach 只能改写已有事实或提出建议；Audit 在导出前检查无证据数字、职位、证书、时间线和因果表述。证据图不可用时默认阻断，而不是默认通过。

## 7. 如果学生确实会某项技能，但简历没写呢？

系统标记 `NO_EVIDENCE` 并请求补充，不写成“不会”。学生可以在模拟面试或补充材料中提供信息，但必须确认并关联来源后才能进入正式画像。

## 8. 如何处理招聘歧视？

敏感属性不进入匹配。Job/Audit 对风险条件标记 `POLICY_EXCLUDED`，不把它变成学生扣分项，并将不确定情况升级给就业老师或合规人员。系统不自动淘汰候选人。

## 9. 情绪识别会不会越界？

Career Navigator 只进行沟通语气调整和求职压力支持，不作医学诊断。明确危机信号触发人工升级和经地区配置核验的求助资源；号码不由模型临时生成。

## 10. 为什么文档要转 Markdown？

Markdown 便于学生与 Agent 共同查看，也方便行号引用。但系统仍保留原文件和哈希，并将结构化结论关联到 Markdown 区块和原文。仅保留 Markdown 会损失版式和原始证据，因此采用三层结构。

## 11. 为什么选择 AgentTeams？

AgentTeams 提供 Manager–Workers、Matrix 透明协作、人工介入、共享文件和网关凭据治理，与本赛题对多 Agent 状态、证据和安全的要求一致。CampusMatch 在其上定义就业场景的 Agent Identity、Skills 和数据契约。

## 12. Demo 如何保证现场稳定？

提供离线确定性和在线 AgentTeams 两种模式。离线模式使用固定夹具和规则，确保没有 API Key 也能运行；在线模式展示真实协作。在线失败时明确降级，不用录好的结果冒充实时成功。

## 13. 没有真实高校数据，怎么证明价值？

初赛用官方就业政策、合成数据和可验证工程设计证明场景与可行性，不虚构真实试点。入围后计划邀请就业老师进行流程访谈和匿名化可用性评价，真实数据必须经过授权和脱敏。

## 14. 如何评价系统是否可靠？

同时使用 Schema 校验、证据引用校验、人工标注要求状态、安全注入、固定回归集和用户评价。核心目标包括证据覆盖、虚构放行率、风险条件计分率、任务成功率和人工退回率。

## 15. 这套能力能复用到哪里？

文档证据抽取、规则规范化、证据匹配、事实审计、人工审批和 Trace 都是跨场景能力。更换岗位词典和策略后，可用于职业培训、内部人才发展、证书申请等场景，但自动录用/淘汰始终不在产品边界内。

## 16. 商业模式是什么？

优先作为高校就业服务的私有化或 SaaS 辅助工具，按学校工作空间、学生服务量或部署支持收费。开源基础协议、Skills、Schema 和合成评测，商业层提供学校系统适配、权限治理、模型服务和运维支持。初赛重点仍是开源复用和工程闭环，不夸大商业收入。

## 17. 最大技术风险是什么？

不是模型不够聪明，而是证据错位和边界失控。对应措施是原文件哈希、证据引用、结构化 Schema、独立 Audit、人工审批、固定评测集和离线降级。

## 18. 为什么项目有获胜潜力？

它来自参赛者可真实理解的大学生求职场景，同时把问题提升到高校组织级基础设施；多 Agent 不是装饰，每个身份都有独立输入、输出、权限、失败模式和评测；最关键的异常分支——无证据经历被阻断——可以现场、稳定、可审计地展示。
