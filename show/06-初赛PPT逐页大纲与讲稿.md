# 初赛 PPT 逐页大纲与讲稿

建议页数：14 页
建议讲解：8–10 分钟
核心叙事：真实就业服务压力 → 黑盒推荐缺陷 → 证据驱动闭环 → AgentTeams 工程化 → 可复现与开放价值

## 第 1 页｜封面

标题：CampusMatch
副标题：高校可信求职协同基座
一句话：让每项匹配和建议都能回到证据

讲稿：

> CampusMatch 不是一个替学生包装经历的聊天机器人，而是一套面向高校就业服务的多 Agent 基础设施。它连接学生材料、岗位要求、匹配理由、辅导建议和审计记录，让每项结论都能回到证据。

## 第 2 页｜高校需要“精准服务”，但个性化辅导难以规模化

可见内容：

- 2026 届普通高校毕业生规模预计 1270 万。
- 高校持续被要求提供专业化、精准化就业服务。
- 学生材料、岗位 JD 和辅导请求均呈高并发、非结构化特征。

讲稿：

> 场景不是虚构的。高校就业中心需要在短时间内处理大量学生材料和岗位，同时还要提供个性化服务。问题不是缺一个聊天框，而是缺一套可复核、可协作、可规模化的任务系统。

来源：

- [教育部：2026 届高校毕业生就业工作](https://www.moe.gov.cn/jyb_xwfb/s5147/202606/t20260615_1440719.html)
- [教育部：就业公共服务进校园百日行动](https://hudong.moe.gov.cn/jyb_xxgk/moe_1777/moe_1779/202604/t20260403_1432954.html)

## 第 3 页｜现有工具把三种不同问题混成一个分数

左侧：

- 简历没写出来
- 学生确实不会
- 岗位要求本身不合理

右侧结论：

> “没有证据”不等于“没有能力”；风险条件更不应成为扣分项。

讲稿：

> 一个黑盒分数无法区分缺证、能力差距和岗位风险，也无法告诉就业老师该如何介入。这正是我们选择证据链作为基础设施核心的原因。

## 第 4 页｜CampusMatch 把求职建议变成可回放的证据链

流程：

```text
原始材料 → Markdown → 能力证据 → 岗位要求 → 匹配矩阵 → 辅导 → 审计 → 人工批准
```

四个关键词：可追溯、可解释、可审批、可复用。

## 第 5 页｜一条完整任务链覆盖输入、执行、验证和沉淀

可见步骤：

1. 授权与目标
2. 文档规范化
3. 学生画像
4. 岗位规范化
5. 证据匹配
6. 求职辅导
7. 审计与审批
8. 报告与经验沉淀

异常分支：缺材料、工具失败、无证据事实、歧视性条件、危机信号。

## 第 6 页｜AgentTeams 让六类 Agent 透明协作

中心：Career Navigator / Manager
Workers：Profile、Job、Match、Coach、Audit
底层：Skills、MCP/工具、共享文件、Trace
右侧：人可进入 Matrix 房间观察、纠正、批准。

讲稿：

> Manager 只做目标、编排和汇总，五个 Worker 各自负责单一能力。大文件通过引用共享，不在对话中重复复制；Worker 不持有真实凭据，外部调用经网关治理。

来源：[AgentTeams 官方仓库](https://github.com/agentscope-ai/AgentTeams)

## 第 7 页｜每个 Agent 都有明确的自主边界

建议用表格展示：

| Agent | 主要输出 | 不可越过的边界 |
|---|---|---|
| Profile | 学生画像＋证据 | 不推断无证据能力 |
| Job | 规范化要求＋风险 | 风险条件不计分 |
| Match | 逐项状态＋置信度 | 不作录用决定 |
| Coach | 建议＋模拟面试 | 不虚构经历 |
| Audit | PASS/BLOCK/ESCALATE | 不自行创造证据 |

## 第 8 页｜三层证据链，让每项能力回到原文

展示一个证据对象：

```text
claim: 具备办公与信息处理经验
evidence: E-S001-003
source: “我使用 Excel 维护活动报名名单，核对参与者信息。”
strength: direct
confirmed: true
```

讲稿：

> Markdown 便于学生和 AI 共同查看，但原始文件仍只读保留并计算哈希。每项结构化能力都关联区块、原文和确认状态。

## 第 9 页｜匹配度与证据覆盖度分开展示

左侧：环形图“匹配度 77”与“证据覆盖度 85%”。
中间：五维雷达图。
右侧：来自当前合成案例的要求矩阵：

- Excel 信息整理：符合
- 基础文档写作：部分符合
- 内容发布经验：缺少证据
- 女性优先：风险排除，不参与评分

状态：符合、部分符合、缺少证据、冲突、风险排除。

页脚注明：合成演示数据，不代表录用概率；缺少证据不等于缺少能力。

## 第 10 页｜Audit Agent 在导出前设置两道门

前置：授权、最小数据、JD 公平、工具权限。
后置：经历真实性、证据覆盖、隐私、内容安全、Trace 完整性。

演示案例：Coach 写出“效率提升 30%”，材料中没有证据 → `BLOCK` → 删除或补证 → `PASS`。

来源：

- [个人信息保护法](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i)
- [人力资源市场规范管理通知](https://app.www.gov.cn/govdata/gov/202408/29/518774/article.html)

## 第 11 页｜Skills 把专家流程沉淀为可复用能力

按四组展示：

- 材料：文档转 Markdown、证据抽取、隐私最小化
- 岗位：JD 规范化、风险扫描
- 决策：证据匹配、分数解释、差距计划
- 治理：事实审计、内容安全、报告导出、SLS 查询

讲稿：

> Skill 定义输入、输出、失败处理和安全边界；MCP 或等价契约负责连接文件、岗位、知识库和日志系统。我们不按工具数量堆砌，而按必要性和可替换性设计。

## 第 12 页｜固定异常分支，验证系统真正可控

演示路径：

```text
合成简历＋岗位
→ 证据画像
→ 匹配可视化
→ Coach 无证据数字
→ Audit 阻断
→ 人工修复与批准
→ 报告＋Trace
```

两条已验证链路：

- 浏览器确定性链路：50 项自动化测试通过，固定案例输出 77 / 85。
- HiClaw Team 实机链路：6 个 Worker、5 个专业阶段，最终业务状态 `READY`。

讲稿：

> 浏览器路径让非技术评委可以稳定复现；HiClaw Team 路径证明多 Agent 的真实委派、状态传递和人工审批门已经打通。Audit 在未批准时返回 `BLOCK + APPROVAL_REQUIRED`，不会自动越权导出。

## 第 13 页｜固定数据 + 实机链路：当前可复现证据

本地 MVP 实测（2026-08-14）：

- 自动化测试：50 项全部通过
- 浏览器控制台错误：0
- 歧视条件进入评分：0
- Worker MCP 健康：6 / 6
- Team 专业阶段完成：5 / 5
- 最终业务状态：`READY`

验证面：浏览器桌面/移动端、API、MCP、Worker Skills、Team Room 与共享结果。77 / 85 为合成案例输出，不代表录用概率或真实招聘效果。

## 第 14 页｜从高校场景出发，开放一套可信求职 Agent Infra

开放内容：Agent Identity、Skills、Schema、合成数据、评测用例、工具适配器、Trace 示例。
扩展方向：高校就业中心、职业培训、校招平台。
结束语：

> 不替学生编造经历，不替企业自动淘汰；让每一次匹配都有证据，让每一次自动化都能被人接管。

## PPT 统一设计建议

- 16:9 白底，黑色主文字，浅灰结构区，蓝色突出“证据”和“通过”。
- 每页只保留一个结论型标题。
- 重要流程使用细线和大留白，避免密集 UI 卡片。
- 图表数据全部标注“合成演示”或“目标指标”。
- 外部数据和非平凡主张在演讲者备注添加 `[Sources]` 区块。
